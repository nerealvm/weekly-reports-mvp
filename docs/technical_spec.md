# Technical Spec: Weekly Collector через `Активные`

## Цель

Заполнять еженедельный отчет Евгению прямо во вкладке Google Sheets `Активные`, без создания отдельного набора `Weekly MVP`, `Weekly Questions`, `Weekly Sync` вкладок.

## Source of truth

- Spreadsheet: `14vjMSr2YaGRcD9Ud1zrDvULhEIE6o5kmZkKfdxarSFs`
- Основная вкладка: `Активные`
- `gid`: `0`

Collector читает `Активные` как таблицу с двухстрочной шапкой:

- строка 1: смысловые группы колонок;
- строка 2: даты недель внутри групп.

Код не должен полагаться на фиксированные буквы колонок. Все рабочие колонки находятся по текстам заголовков.

## Рабочие поля

### Базовые поля строки

| Поле в `Активные` | Локальное поле |
| --- | --- |
| `Тема` | `topic_title` |
| `Дата постановки` | `date_created` |
| строка-секция слева (`Проекты`, `Задачи`, etc.) | `section` |

`Topic ID` во вкладке `Активные` не хранится. На время collector-сессии строки получают сквозные ID по порядку: `T-001`, `T-002`, ...

### Недельные группы

| Группа | Локальное поле | Логика |
| --- | --- | --- |
| `Статус предыдущей недели` | `previous_week_result` | для новой недели копируется из предыдущей колонки группы `Куда мы докатились на этой` |
| `Куда мы докатились на этой` | `final_result` | главный итог текущей недели |
| `Когда докатимся и куда` | `milestones[]` / `next_milestone` | ближайшие шаги и сроки |

### Постоянные поля

| Поле в `Активные` | Локальное поле |
| --- | --- |
| `На чьей стороне мяч` | `ball_side` |
| `Открытые вопросы` | `open_question_to_evgeny` |

Эти поля не размножаются по неделям.

## Основной сценарий

1. Пользователь запускает collector:

```bash
make collector WEEK_START=2026-06-05 WEEK_END=2026-06-12 COLLECTOR_REFRESH=--refresh
```

2. Collector скачивает CSV вкладки `Активные`.
3. Collector парсит шапку и находит группы колонок.
4. Collector строит локальную session:
   - берет только строки с темами;
   - присваивает `T-001`, `T-002`, ...;
   - подтягивает текущий результат, вехи, мяч и открытые вопросы;
   - для новой недели берет `previous_week_result` из предыдущего результата.
5. Пользователь заполняет фактуру вручную в UI или через ChatGPT Project.
6. `Write Active`:
   - создает недостающую дату недели в трех группах, если ее еще нет;
   - пишет `previous_week_result` в `Статус предыдущей недели`;
   - пишет `final_result` в `Куда мы докатились на этой`;
   - пишет вехи в `Когда докатимся и куда`;
   - обновляет `На чьей стороне мяч` и `Открытые вопросы` только когда эти поля изменены.

## ChatGPT Project

Prompt живет в `docs/chatgpt_weekly_project_prompt.md`.

Правило: ChatGPT не сочиняет отчет, а почти дословно раскладывает сказанное пользователем по полям:

- `current_week_facts`: почти дословная сырая фактура;
- `final_result`: что реально произошло на этой неделе;
- `milestones[]`: новые сроки/шаги, только если пользователь их сказал;
- `ball_side`: сохранять прежнее значение, если пользователь явно не поменял мяч;
- `open_question_to_evgeny`: только явный вопрос к Евгению.

Запрещено добавлять факты, даты, решения, риски, выводы и артефакты, которых пользователь не сказал.

## Что больше не является основным путем

- Не создавать новую `Weekly MVP <date>` вкладку для каждой недели.
- Не создавать `Weekly Questions` и `Weekly Sync` вкладки.
- Не использовать `Legacy row` как обязательный механизм сопоставления.
- Не писать по жестким диапазонам вроде `H:S`; запись идет по найденным заголовкам.

Legacy-код для старого нормализованного сценария оставлен для совместимости и тестов, но основной collector-путь работает через `Активные`.

## Ограничения

- Перенос строки между вкладками `Активные`, `Архив`, `Закрытые` остается ручным действием в Google Sheets.
- `Archive` в collector скрывает строку в локальной session, но не переносит строку между вкладками.
- Если пользователь не назвал новую веху, ChatGPT возвращает пустой `milestones[]`; collector не должен автоматически копировать старую веху как новую.
