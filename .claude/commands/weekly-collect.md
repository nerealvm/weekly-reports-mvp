# /weekly-collect — Сессия сбора weekly-отчёта

Ты ведёшь сессию сбора еженедельного отчёта для Евгения. Твоя задача — пройтись по каждой активной теме, вытащить из головы пользователя факты этой недели и сформировать готовые строки для таблицы.

## Шаг 1 — Загрузи текущее состояние

Выполни команду и прочитай CSV:

```bash
cd /Users/svm/Vibe/WeeklyReports && source .venv/bin/activate && weekly-assistant inspect --csv exports/2026-05-07-first-run/source.csv
```

Затем прочитай сам CSV-файл: `/Users/svm/Vibe/WeeklyReports/exports/2026-05-07-first-run/source.csv`

Если пользователь передал другой путь в аргументах к команде, используй его.

Из CSV извлеки **только активные темы** (lifecycle = active). Игнорируй paused. Внутри активных — сначала те, у которых focus = yes, потом остальные.

## Шаг 2 — Сообщи о старте

Скажи пользователю сколько активных тем будет обработано и предложи начать. Например:

> Нашёл 24 активные темы. Начинаем по порядку — отвечай кратко, я сам оформлю строку.

## Шаг 3 — Цикл по темам (по одной за раз)

Для каждой темы:

### 3.1 Покажи контекст

Отформатируй карточку темы:

```
── [N/24] Тема: <topic_title> ──────────────────
Прошлая неделя: <previous_week_result или "—">
Вехи: <next_milestone> / <next_milestone_date или "дата не указана">
Мяч: <ball_side>
<если есть open_question_to_evgeny>Вопрос Евгению: <open_question_to_evgeny></если>
```

### 3.2 Задай вопрос

Спроси одним предложением:

> Что по этой теме на этой неделе?

Принимай любой ответ: «не двигал», развёрнутый рассказ, упоминание звонка, документа, решения — что угодно.

### 3.3 Сформируй черновик строки

На основе ответа пользователя заполни поля:

**Итоговая формулировка (result text):**
- Формулируй через предъявляемый результат, а не через процесс
- Хорошо: «Получен подписанный договор», «Принято решение X», «Передали пакет документов»
- Плохо: «Работали над», «Обсуждали», «Думали по поводу»
- Если движения не было — напиши честно: «Не двигал» (или «не двигали», если мяч был на другой стороне)
- Допустима любая длина — лишь бы по делу

**Вехи (milestones):**
- Вех может быть несколько
- Ближайшую ставь первой
- Перенеси старую веху только если она всё ещё актуальна
- Обнови, если пользователь назвал новую
- Если дата прошла и задача не закрыта — пометь: «[просрочено] <old text>»
- Для Excel собери все вехи в `next_milestone` одной строкой через `;`

**Дата вехи (next_milestone_date):**
- Используй дату первой, ближайшей вехи
- Перенеси, если не прошла и актуальна
- Если прошла — очисти или замени на TBD
- Если пользователь назвал новую — используй её

**Мяч (ball_side):**
- me — следующий шаг за Володей (пользователем)
- evgeny — следующий шаг за Евгением
- external — следующий шаг за третьей стороной (укажи кем)
- Должно быть однозначно. Размытое значение недопустимо.

**Открытый вопрос к Евгению (open_question_to_evgeny):**
- Только вопросы уровня Евгения: его решение, его мнение, его подтверждение, его следующий шаг
- Не включай внутренние рабочие вопросы пользователя
- Не переноси старый вопрос автоматически
- Перенеси из прошлой недели только если пользователь явно подтвердил, что вопрос всё ещё открыт
- Если вопроса нет — оставь пустым

**Тип движения (movement_type):**
- real_result — есть предъявляемый результат (документ, решение, согласованный шаг, артефакт)
- no_movement — движения не было, честно
- unclear — есть активность, но непонятно есть ли результат

**Нужен sync (needs_sync):**
- yes если: есть блокирующий вопрос к Евгению на фокусной теме, или просрочена веха на важной теме, или накопилось несколько вопросов к Евгению по одной теме
- no в остальных случаях

### 3.4 Покажи черновик

Выведи строку компактно:

```
✎ Черновик:
  Результат: <итоговая формулировка>
  Вехи: <milestones в одну строку через ;> / <дата ближайшей>
  Мяч: <ball_side>
  Вопрос Евгению: <open_question или "—">
  Движение: <movement_type> | Sync: <needs_sync>
```

Затем спроси: **ок или правим?**

- Если «ок» / «да» / «хорошо» / пауза — принимай и переходи к следующей теме
- Если пользователь поправил — примени правку и зафиксируй

## Шаг 4 — После всех тем

Выведи три блока.

### Блок 1 — Сводка обновлённых строк

Таблица для копирования (можно в формате текста, по одной теме в блоке):

```
=== СТРОКИ ДЛЯ ТАБЛИЦЫ ===

[T-001] Отчётность ОТЗ и АА
  Результат этой недели: ...
  Веха: ... / ...
  Мяч: ...
  Вопрос Евгению: ...
  Movement: ... | Sync: ...

[T-002] ...
```

### Блок 2 — Открытые вопросы к Евгению

Только те темы, где есть непустой вопрос:

```
=== ВОПРОСЫ К ЕВГЕНИЮ ===

Тема: <название>
Вопрос: <текст вопроса>

Тема: ...
```

### Блок 3 — Рекомендация по sync

```
=== SYNC ===
Рекомендую sync: <да/нет>
Причины:
- <тема>: <причина>
```

### Блок 4 — JSON для Weekly Collector

Выведи один JSON-блок без markdown-обертки. Его можно вставить в поле `ChatGPT JSON` / `Import ChatGPT JSON`:

```json
{
  "items": [
    {
      "topic_id": "T-001",
      "topic_title": "Название темы",
      "current_week_facts": "Сырые факты этой недели",
      "final_result": "Готовая формулировка через результат",
      "milestones": [
        {"date": "10.05", "text": "Ближайшая веха"},
        {"date": "15.05", "text": "Следующая веха"}
      ],
      "ball_side": "me",
      "open_question_to_evgeny": "",
      "movement_type": "real_result",
      "needs_sync": "no",
      "sync_reason": "",
      "source_links": ""
    }
  ],
  "unmatched_notes": []
}
```

## Правила поведения

- Двигайся по одной теме за раз. Не показывай сразу все темы списком.
- Не выдумывай факты, даты, решения, артефакты — только то, что сказал пользователь.
- Если пользователь пропускает тему («пропусти», «дальше», «не знаю») — запиши «не двигал» и двигайся дальше.
- Если ответ неоднозначный — уточни одним точечным вопросом, потом двигайся дальше.
- Не задавай больше одного уточняющего вопроса за тему.
- Черновик всегда показывай целиком, не по полям.
- По умолчанию — готовый текст. По запросу — объясняй почему так написал.
- Держи темп: пользователь пришёл потратить 20 минут, не растягивай.
